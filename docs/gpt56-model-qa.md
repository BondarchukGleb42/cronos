# GPT-5.6 через AllTokens: проверка интеграции

Дата: 8 сентября 2026. Проверены авторизованный каталог AllTokens, синтетические HTTP-запросы и текущий локальный `Provider.complete`. Это проверка совместимости и учёта расходов, **не сравнительный тест качества моделей** и не подтверждение выкладки нового кода.

## Каталог и стоимость

Авторизованный `GET /models` вернул HTTP 200 и 444 модели. Для трёх проверенных моделей каталог указал `pricing_units.prompt=pricing_units.completion=rub_per_1m`:

| Model ID | Вход, ₽ / 1 млн токенов | Выход, ₽ / 1 млн токенов |
|---|---:|---:|
| `openai/gpt-5.6-luna` | 25 | 150 |
| `openai/gpt-5.6-terra` | 230 | 1380 |
| `openai/gpt-5.6-sol` | 230 | 1150 |

Это снимок цен провайдера, не зафиксированный тариф. У Luna фактический `usage.cost` соответствовал ставкам 24,84/149,04 ₽, немного отличающимся от округлённого каталога. Для списания используется точная стоимость ответа, а не пересчёт по каталогу.

Все три записи заявляли контекст 1 050 000 токенов, вход `file/image/text`, выход `text` и одинаковый список `supported_parameters`:

```text
include_reasoning, max_completion_tokens, max_tokens, reasoning,
reasoning_effort, response_format, seed, structured_outputs, tool_choice, tools
```

`temperature` и `top_p` в этом списке отсутствовали; проверенные запросы их не передавали. Официальная [карточка GPT-5.6 Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna) также описывает режимы `none` и `high`, function calling и вход с изображениями; совместимость именно AllTokens подтверждалась отдельными запросами ниже.

## Реальный `Provider.complete`

Проверены Luna, Terra и Sol с `reasoning=False/True`: шесть HTTP 200, у каждого одна успешная попытка, непустой ответ, сохранённый выбранный `usage.model`, известная стоимость и request ID. Подменён только сетевой транспорт: HTTP-запросы SDK передавались через `curl --interface en0`. Формирование payload, разбор ответа/SSE и нормализация usage выполнялись текущим кодом Provider.

На проводе проверены:

```json
{"reasoning_effort": "none", "max_completion_tokens": 512}
```

```json
{"reasoning_effort": "high", "max_completion_tokens": 1024}
```

| Модель | Reasoning-токены при `none` | При `high` | Стоимость `none`, ₽ | Стоимость `high`, ₽ |
|---|---:|---:|---:|---:|
| Luna | 0 | 226 | 0,00178848 | 0,03576960 |
| Terra | 0 | 176 | 0,02484000 | 0,26220000 |
| Sol | 0 | 208 | 0,01541000 | 0,25691000 |

Оба режима получили одинаковую задачу: восемь итераций `x=(x*37+11)%101` от `x=17`, с просьбой вывести только итог. Локальный эталон — 62. Все глубокие ответы совпали с эталоном; ответы без reasoning в этой задаче были неверны. Это помогает проверить переключение режима, но не позволяет оценивать общую точность моделей по одному примеру.

Глубокий запрос Luna прошёл через **реальный SSE**: итоговый ответ, usage и стоимость сохранены, `on_delta` вызван один раз. Ограничения вывода не исчерпаны, `finish_reason=stop`. В отдельных прямых HTTP-пробах также подтвердился вложенный вариант `reasoning: {"effort":"high"}` для всех трёх моделей. Для интеграции оставлен верхнеуровневый `reasoning_effort`.

## Инструменты, изображения и usage

- Все три модели вернули корректный вызов синтетической функции `record_number` с JSON-аргументом `{"value":42}` и `finish_reason=tool_calls`. Проверялись schema и принудительный `tool_choice`; реальное внешнее действие не выполнялось. Полный следующий ход с результатом инструмента в этой QA-сессии не проверялся.
- Luna приняла inline PNG 96×96 и правильно назвала цвет изображения. Vision Terra/Sol и файловый вход подтверждены только каталогом, без отдельных live-проб.
- Ответы содержали `usage.cost`, `cost_details`, `prompt_tokens`, `completion_tokens` и `completion_tokens_details.reasoning_tokens`. Отдельного поля валюты не было. У Terra/Sol стоимость точно совпала с арифметикой каталога в рублях: например, `42×230/1e6 + 200×1150/1e6 = 0,23966` ₽.
- Reasoning уже входит в `completion_tokens` и указанную стоимость; повторно прибавлять его нельзя. Наличие reasoning определяется по usage и выбранному режиму, а не по непустому текстовому полю `message.reasoning`: у одного ответа Sol это поле было пустым при ненулевых reasoning-токенах.

Суммарно: 17 прямых синтетических HTTP-проб — **1,26395856 ₽**; шесть вызовов текущего Provider — **0,59691808 ₽**; всего **1,86087664 ₽**, неизвестных стоимостей нет. TLS-проверка оставалась включена. Секреты передавались в памяти/stdin, не записывались в отчёты или аргументы процессов. Telegram, БД и production при этой проверке не изменялись.

Обезличенные подробности текущей локальной QA-сессии сохранены во временных файлах `/tmp/cronos-gpt56-live-qa.json`, `/tmp/cronos-gpt56-qa.jsonl`; вызовы воспроизводятся отдельными временными helper-скриптами. Основные результаты полностью приведены выше, поскольку содержимое `/tmp` не является постоянным хранилищем доказательств.

## Полный сценарий агента и совместимость аргументов

Дополнительно выполнен настоящий `Agent.run` с Luna без рассуждения, 46 доступными инструментами и изолированной PostgreSQL. В первых двух проходах модель корректно выбрала `memory_write`, но передала необязательные `project_id` и `supersedes_id` пустыми строками. Обработчик считал их заданными ID и отклонял запись общей памяти. Модель получила реальную ошибку инструмента и сообщила о неуспехе.

После исправления пустые необязательные ID означают отсутствие значения, схема явно допускает `null`. Непустые и обязательные ID по-прежнему проверяются, пустая дата не превращается в бессрочное хранение. Аналогичный случай учтён на входе инструментов проектов, планов, поиска и создания сценариев.

Повтор полного сценария прошёл: факт записан в общую память со ссылкой на текущий event, второй запрос модели получил успешный результат инструмента, финальный ответ непустой. Проверены checkpoints, пара сообщений в истории и завершённый run. Финальный проход после общей нормализации аргументов тоже прошёл: два HTTP-запроса стоили **0,35619318 ₽**, четыре диагностических прохода вместе — **1,36985148 ₽**. Использовался только синтетический пользователь в локальной тестовой БД; после проверки он полностью удалён. Telegram transport и outbox-доставки отсутствовали. Это дополняет раннюю проверку вызова функции полноценным продолжением после её выполнения.
