# Изображения и альбомы

Альбом Telegram обрабатывается как один запрос со всеми вложениями и подписями. Ingress сохраняет каждый update и объединяет сообщения одного пользователя, чата, темы и `media_group_id` в PostgreSQL. Новое вложение откладывает обработку на две секунды; повторы update не продлевают ожидание. Текстовая инструкция, пришедшая в эту же тему во время сборки, присоединяется к альбому; команды, навигация и подтверждения удаления обрабатываются отдельно. После старта обработки вход запроса неизменяем. Редкое запоздалое продолжение сохраняет весь набор в истории и уведомляет пользователя без повторной платной генерации.

Worker сохраняет все файлы до обращения к модели. Если хотя бы одно вложение не удалось скачать, генерация по неполному набору не начинается. В истории и LangGraph хранятся небольшие ссылки `image_ref` с `artifact_id`, а пиксели подставляются только в запрос провайдеру с проверкой владельца. Модель видит текст и все изображения последнего визуального сообщения; предыдущие артефакты остаются доступны инструментам. Старые текстовые указатели на файлы тоже поддержаны. Для визуального контекста используется уменьшенная копия, для генератора — оригинальные PNG/JPEG/WebP; остальные форматы нормализуются в PNG.

`image_generate` принимает `artifact_ids` всех исходников/референсов и текстовую инструкцию. Если список опущен, берутся изображения последнего визуального сообщения. Явный пустой список означает генерацию с нуля. AllTokens получает массив блоков `text` + `image_url` через Chat Completions с `modalities=[image,text]`. При повторе исходники сохраняются; отката к генерации без изображений нет. Текущая модель поддерживает до 14 референсов; больший набор не обрезается молча. Редактирование не принуждается к квадратному формату.

Успешный инструмент сохраняет картинку, а финальный ответ Worker объединяет её с подписью в одном outbox payload. Сбой модели при составлении подписи не теряет уже подготовленную картинку. Сгенерированный артефакт сохраняется в истории для следующего редактирования. Для одной картинки и подписи до 1024 UTF-16 единиц отправляется один `sendPhoto`; промпт просит подпись до 900 символов. При превышении лимита Telegram текст продолжается отдельным сообщением без потерь. Несколько результатов отправляются по очереди, подпись относится к первому; частичная доставка сохраняет только неотправленный остаток.

Подпись финального ответа имеет `format=rich`. Поддерживаемый Markdown преобразуется в видимый текст и `caption_entities`, а не передаётся Telegram как сырой Markdown. Жирный текст, курсив, зачёркивание, спойлеры, код и ссылки работают в той же фотографии; заголовки отображаются жирным. Разбиение выполняется после форматирования, с корректными UTF-16 смещениями и переносом entities в продолжение. HTML и неподдерживаемая/незавершённая разметка остаются буквальным текстом. Обычные подписи файлов без `format=rich` не меняются. При явном отказе Telegram разобрать entities повторяется только заведомо отклонённая отправка с уже очищенным текстом; сетевые ошибки не запускают повторную загрузку. Rich-блоки основного текстового ответа продолжают отправляться через `sendRichMessage`.

Визуальные ходы не показывают промежуточные реплики до решения о вызове инструмента. Если ответ модели одновременно содержит вопрос и вызов генерации, ход заканчивается вопросом и ждёт ответа пользователя. При ясном запросе промпт требует выполнить изменение без уточнения необязательных деталей.

До первого текста ответа draft содержит «Думаю...». Пока запрос выполняется, Worker каждые четыре секунды обновляет последний draft. Обновления изолированы по чату, теме и запуску; placeholder не заменяет уже пришедшие токены. Обновление останавливается перед финальной доставкой и при отмене. Все обращения к Telegram, включая файлы и draft, используют `TELEGRAM_PROXY`.

API: [Telegram media_group_id](https://core.telegram.org/bots/api#message), [caption](https://core.telegram.org/bots/api#sendphoto), [reply keyboard](https://core.telegram.org/bots/api#replykeyboardmarkup), [AllTokens inputs](https://docs.alltokens.ru/concepts/image-inputs/), [image generation](https://docs.alltokens.ru/concepts/image-generation/).
