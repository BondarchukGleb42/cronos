# Отдельные чаты и названия тем

Документ описывает реализацию в текущей рабочей версии. Наличие кода не подтверждает его развёртывание или доступность всех элементов интерфейса Telegram.

## Пользовательский сценарий

- `/new` и кнопка «➕ Новый чат» создают настоящую тему в личном чате с ботом. После создания бот отправляет приветствие в новую тему. Попросить создать тему можно и обычным текстом через инструмент `topic_create`.
- `/chats` показывает до 30 сохранённых названий и кнопку создания чата. Все доступные темы и переключение между ними находятся в штатном списке тем Telegram.
- Пользователь также может создавать темы средствами самого Telegram, если владелец бота включил соответствующее разрешение. Служебные события создания и переименования синхронизируются с Cronos.
- История разговора разделена по темам; сохранённая память и предпочтения общие для пользователя. Новый чат не стирает память и не подмешивает историю другой темы.
- Явное название, заданное пользователем при создании темы в Telegram или при ручном переименовании, закрепляется: автоматическое переименование отключается для этой темы.

Cronos не обещает автоматически переключить открытый экран Telegram. Документированного jump URL для конкретной темы **личного чата с ботом** нет, поэтому такие ссылки не строятся. Обычная ссылка открывает самого бота. Официальное описание [forum topic links](https://core.telegram.org/api/links#forum-topic-links) относится к ссылкам на сообщения и темы групп/каналов.

## Автоматическое название

Первое название ставится после сохранения первого сообщения пользователя и ответа ассистента. Следующие обновления запрашиваются на отметках **10, 20, 30… сообщений суммарно**, а не через каждые десять пар. Считаются только сохранённые сообщения `user` и `assistant`, не исключённые из истории. Служебные события, вызовы инструментов и генерация самого названия в этот счётчик не входят. Для обычного диалога без native topic автоматическое название не создаётся.

`MODEL_TITLE` выбирает отдельную модель; значение по умолчанию — `meta-llama/llama-3.1-8b-instruct`. [Публичный каталог AllTokens](https://alltokens.ru/models/meta-llama/llama-3.1-8b-instruct) подтверждает доступность этой небольшой текстовой модели. Разговорная модель и её резервные маршруты при создании названия не используются.

В запрос передаются максимум четыре последних текстовых сообщения по 800 символов и прежнее название. История рассматривается как данные, инструменты и поиск не подключаются. Лимит ответа — 64 токена; таймаут одного запроса — 10 секунд. Предпочтение 2–6 словам задаётся в промпте, но короткая фраза сохраняется целиком. Название длиннее 64 символов или 128 байт UTF-8 отклоняется с сохранением данных о стоимости вместо обрезки слов.

## Выполнение и восстановление

Переименование — отдельное сохраняемое событие `topic_title` в PostgreSQL, которое обрабатывает существующий Worker. Основной ответ не ждёт генерации названия. Новые процессы, базы и очереди не добавляются.

Событие различается по пользователю, теме, ревизии и порогу счётчика. Перед работой проверяются актуальность ревизии и разрешение автоматического названия. Ручное переименование меняет ревизию и отключает автоматику, поэтому старое задание не должно заменить выбор пользователя.

Результат модели сохраняется до вызова Telegram `editForumTopic`. Если Telegram не подтвердил переименование, повтор обработки использует уже сохранённый результат модели. Стоимость проходит через существующий механизм резервирования и учёта usage. Пустой или слишком длинный ответ модели не считается успешным названием.

Создание темы также сохраняет намерение операции: при неопределённом результате Telegram повтор не создаёт ещё одну тему вслепую.

## Включение и границы проверки

Последний runtime-снимок `getMe` для `@cronos_ait_bot` от **06.09.2026**:

| Поле | Значение | Что требуется |
| --- | --- | --- |
| `has_topics_enabled` | `false` | Включить Topics Mode для бота в BotFather |
| `allows_users_to_create_topics` | `false` | Разрешить пользователям создавать и удалять темы через native UI |

Это независимые возможности: первая необходима для работы тем, вторая — для самостоятельного создания пользователем через Telegram. `/new` и кнопка вызывают создание от имени бота и проверяют первую. Значения описаны в официальном объекте [User, возвращаемом getMe](https://core.telegram.org/bots/api#user). Успешный ответ `getMe` кешируется на 60 секунд, после чего изменения BotFather могут быть обнаружены без перезапуска.

Код и тесты покрывают создание, раздельную историю, пороги именования, ручное название, повтор обработки и недоступность режима. Реальная генерация русского названия через AllTokens проверена: «Питание и тренировки для набора мышц». **Полный сценарий в живом UI Telegram пока не подтверждён**: после включения обоих параметров нужно проверить создание кнопкой и native UI, переключение, появление автоназвания и сохранение ручного названия.

Основные проверки реализации:

```sh
uv run pytest -q tests/test_topics.py tests/test_topic_title_provider.py tests/test_storage.py tests/test_telegram.py
```

Для интеграционных проверок `test_storage.py` нужен отдельный тестовый PostgreSQL, как описано в [README](../README.md#разработка). Пока Topics Mode выключен, Cronos сообщает об этом и продолжает поддерживать обычный чат.
