## Что реализовано

- Общий агент LangGraph: повседневные и рабочие задачи, память между темами,
  персональные предпочтения, каталог собственных навыков и управление свободным текстом.
- Поиск с источниками через Sonar, reasoning, vision, создание и правка изображений.
- Чтение PDF/CSV/XLSX/DOCX/TXT и изображений, анализ таблиц и создание документов.
- Явные напоминания, повторения и инициативные продолжения с согласием и тихими часами.
- Повышение тестового тарифа одной кнопкой, пополнения и учёт фактического usage.
  `ALPHA_SOFT_LIMITS=true` допускает отрицательный баланс без тарифной блокировки.
- Все вызовы Telegram, включая polling, черновики, ответы и файлы, используют
  обязательный `TELEGRAM_PROXY`. Прямого fallback нет; DNS разрешает proxy.

## Выбор модели и исправления

Базовая модель для всех тарифов альфы — `deepseek/deepseek-v4-flash`. В живом сравнении
Nemo подтвердил запись без вызова инструмента и без изменения БД; DeepSeek выполнил
реальные операции памяти и передал точные русские данные CSV. Qwen на отдельной
SSE-проверке ответил HTTP 429 с сообщением о временной перегрузке модели.

Для 429 добавлены задержки 1/2 секунды либо Retry-After до 30 секунд, максимум три
попытки. Неоднозначно прерванный оплачиваемый SSE повторно не отправляется. Генератор
CSV теперь сохраняет ячейки как при структурированных rows, так и при готовом CSV-тексте;
сочетание columns и content не теряет строки, несовпадающие заголовки отвергаются.

Остановка PID 1 проверена на живых контейнерах с тем же кодом жизненного цикла, коммит
`9c223bc`. Перед каждым сигналом активных пользовательских задач было ноль:

| Контейнер | Завершение с кодом 0 | Возврат в Ready |
| --- | --- | --- |
| worker | 3,30 с | 11,81 с |
| coordinator | 6,76 с | 18,65 с |

Каждому процессу послан один SIGTERM, без принудительного kill. Это заменило исходное
ожидание 180 секунд. Coordinator получил лимит 256 MiB после подтверждённого OOM при 192 MiB.

## Ресурсы и конфигурация

Постоянно работают PostgreSQL, RabbitMQ, Redis, gateway и runtime. В runtime два
контейнера — worker/coordinator — с общим PVC файлов. Временные завершённые Jobs удалены
после сохранения результатов.

| Постоянная часть | CPU request / limit | RAM request / limit |
| --- | --- | --- |
| PostgreSQL + RabbitMQ + Redis | 225m / 1100m | 288 / 1024 MiB |
| Gateway + worker + coordinator | 225m / 1450m | 416 / 2048 MiB |
| Всего | 450m / 2550m | 704 / 3072 MiB |

PVC: 5 GiB PostgreSQL, 1 GiB RabbitMQ, 5 GiB файлы. ResourceQuota: requests 2 CPU / 4 GiB,
limits 4 CPU / 6 GiB, PVC 20 GiB; запас включает временные миграции и проверки.

CI использует `YC_SA_JSON_CREDENTIALS`. Kubeconfig выбирается по проверенным endpoint
и CA, а не по имени экспортированного контекста. Ключи и proxy-пароль находятся в Secrets
и передаются окружением; проверка отслеживаемых файлов не нашла действующих credentials.

## Границы проверки

- Vision остаётся на Qwen: ранняя проверка изображения прошла, но отдельный поздний
  probe получил HTTP 429. Этот маршрут зависит от восстановления провайдера.
- Для нативных тем требуется включить Topics в BotFather; код обычного чата от этого не зависит.
- NetworkPolicy на текущем CNI не исполняется. Namespace, квоты, restricted Pod Security,
  отдельные пароли и роль PostgreSQL с RLS проверены; сетевой изоляции между namespaces нет.
  Манифест egress учитывает текущий proxy TCP/8000 для будущего включения enforcement.
- У Telegram нет idempotency key отправки: разрыв после доставки до подтверждения способен
  дать редкий дубль. Подтверждённые части длинного ответа не повторяются.
- Голос, реальные платежи, произвольный запуск кода и внешние персональные интеграции отложены.
